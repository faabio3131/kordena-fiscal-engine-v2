## Decision

CL-12 implements a canonical NFCore-owned trial journey:

```text
signed trial request
 -> explicit trial-eligible plan
 -> NFCore-owned tenant
 -> organization + OWNER
 -> activation delivery
 -> canonical TRIAL subscription
 -> temporary entitlements
 -> expiry to SUSPENDED or internal governed conversion to ACTIVE
```

Trial state remains commercial authority only. It cannot promote fiscal readiness,
provider homologation or `PRODUCTION_APPROVED`.

## Security

- server-to-server HMAC authentication is mandatory;
- authenticated key is rate limited;
- idempotency key is mandatory and persisted only through derived identity;
- browser/request cannot provide tenant identity;
- duplicate trial for an existing OWNER e-mail fails closed;
- extra authority fields are rejected;
- activation reset is never returned in the HTTP payload;
- tenant identity is generated by NFCore;
- conversion is an internal application boundary and is not exposed by the public trial router.

## Trial duration

`PlanDefinition.trial_days` becomes operational only for a canonical subscription
whose billing status is `TRIAL`. Paid subscriptions retain the pre-existing cadence
semantics.

A plan with `trial_days=0` is not trial eligible.

## Expiry / conversion

- a due trial transitions to `SUSPENDED`, preserving existing legitimate fiscal state;
- internal conversion transitions `TRIAL -> ACTIVE`;
- public trial HTTP cannot perform conversion;
- later provider/payment orchestration remains responsible for supplying trusted
  conversion evidence before invoking the internal boundary.
